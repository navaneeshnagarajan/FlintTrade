# FlintTrade v0.6.0-beta - Native app, setup continuity, and release hardening

FlintTrade `v0.6.0-beta` is a beta prerelease. It is not production ready.
The release focuses on making the app usable as a local native-first
workstation while tightening the release, installer, and setup paths.

## Release Metadata

- SemVer: `0.6.0-beta`
- Git tag: `v0.6.0-beta`
- Release type: beta prerelease
- Stability: beta, not production ready
- Primary app surfaces: native desktop app, terminal UI, FlintTrade backend,
  release installers, setup/account flow

## Highlights

- Added the Tauri 2 native desktop app with a PyInstaller backend sidecar, a
  native splash screen, and first-run workspace secret provisioning.
- Moved normal user configuration into Setup, Settings, and workspace state;
  `.env` remains an advanced server fallback rather than a required user step.
- Wired account setup choices into the real app profile, skill-level, trading
  defaults, risk limits, OpenAlgo bridge metadata, and workspace preset state.
- Fixed command-palette keyboard selection and routed global Docs, Changelog,
  fullscreen, layout, widget, and tool actions through the shared app shell.
- Kept Admin navigation dev-only and removed persisted production sidebar
  entries that could otherwise point at a missing route.

## Release And Installer Hardening

- Desktop release CI now runs on version tags as well as manual dispatch, checks
  that release tags match `package.json`, installs PyInstaller from the frozen
  `desktop` extra, and fails if no installer artefacts are staged.
- Native server installers now start `flinttrade_core.app`, not the retired
  `packages.core.src.app` path.
- OpenAlgo systemd setup is opt-in via `INSTALL_OPENALGO_SERVICE=1`; the default
  server target starts FlintTrade only and leaves broker bridge configuration to
  Settings -> Broker Gateway.
- Docker installation now waits on the actual Compose service name,
  `flinttrade`.
- The OSV vulnerability snapshot refresh no longer masks failed `pip-audit`
  executions that do not produce a trustworthy report.

## Verification Notes

This beta has local verification for the setup, workspace, and terminal UI
surfaces touched by the hardening pass. Cross-platform installer builds are
validated by the desktop release workflow and should be reviewed before public
distribution.
